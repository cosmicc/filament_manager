- At the start of repository work and again before release preparation, review every open automated dependency pull request. Merge only updates with compatible engine and peer ranges, a coherent lockfile, successful full CI, and relevant local validation. Never use `--force` or `--legacy-peer-deps` to make an incompatible update install. Defer or close blocked updates with the exact incompatibility, or validate linked major upgrades together on a dedicated branch. Keep dependency-only merges separate from unpublished application changes.
- Review changes directly; CodeRabbit is not used. Test combined dependency candidates in an isolated worktree based on current `main`, run clean installation and dependency-tree validation with the same Node 22 runtime used by CI, and exercise browser refresh/save flows when changing React Query. Verify exact PR head commits and successful checks before merging, then verify the resulting `main` CI. Dependency maintenance must not move an existing release tag.
- Before branch deletion, verify the exact current branch head, open-PR and worktree use, and inclusion in `main`. For squash merges, require the merged PR's recorded head to match the branch and verify its tree against the retained squash commit. Preserve unmerged work and branches of deferred open PRs; delete only the verified refs and prune stale remote-tracking refs afterward.
