# Frontend Design and Accessibility Skill

- React, TypeScript, and Vite are the required frontend stack.
- Use Workshop Navy in `docs/design/palette.png` as the base and the exact three light plus five dark selectable profiles in `docs/design/theme-palettes.svg`. New UI colors must remain inside the selected profile's semantic tokens.
- Use `docs/design/concepts/` as the layout and density reference. Preserve desktop data tables and use purpose-built mobile flows rather than squeezed tables.
- Navigation: Dashboard, Spools, Filaments, Print History, Templates, Calibration Wizard, Build Plates, Printers, Nozzles, Labels, Integrations, Cura Workstations, Diagnostics, Activity, Settings. Filaments provides its own **Catalog** and **Print settings** secondary navigation; keep Profiles out of the top-level shell and redirect the legacy browser `/profiles` path to `/filaments/settings`.
- Templates exposes complete reusable current settings under the canonical `Template <material type>` identity. A filament can own multiple current printer/nozzle-specific settings scopes. Filament detail separates product editing from responsive exact-scope cards with independent Edit, Compare, and Cura JSON export actions, and lets an operator add an unoccupied scope from a compatible active same-material template. Print settings lists the current filament/printer/nozzle matrix. Each profile stores sparse overrides, renders every effective profile-editable template value, visibly highlights customized fields immediately while editing, shows the linked template and inherited/customized counts, and provides per-setting **Reset to Template**. Every blank template setting keeps a visible **Copy from another template** selector populated from every other active template that has that exact value; if none qualify, disable the selector and explain that no populated source exists. Applying a choice changes only the local control until normal Save. Group controls into Cura-like temperature, flow, speed, acceleration, retraction, ironing, cooling, support, dimensional, filament, Klipper, and build-plate sections; never use an Advanced Cura catch-all. Retraction Retract Speed and Retraction Prime Speed are distinct controls. Show all print speeds, smooth time, and the seven acceleration values only in templates with **Template only** labels. Keep every cooling control, pressure advance, and ironing flow/speed/line-spacing value editable on both templates and profiles, while leaving ironing enablement entirely to Cura quality profiles. Regular and Maximum Fan Speed accept zero through 100 percent; Regular Fan Speed at Layer starts at one. Show exactly one primary Flow plus Printing Temperature, Build Volume Temperature, and Build Plate Temperature; do not expose or emit default temperature aliases. Keep acceleration control and travel acceleration enabled in Cura without exposing either toggle. Saving a template immediately updates every current exact scope that still inherits it except for permitted explicit customizations and automatically queues Cura synchronization.
- Filament and spool catalog identities prominently show material type and color together, adding filler and finish only when they differ from the implied `None` filler or `Standard` finish. Vendor, optional display name, and spool code remain visible supporting identity. Filament cards show tolerance and the current printing-temperature scope/range instead of diameter and nominal mass; those physical values remain in details. Product editing resolves the linked template to its current snapshot and lists it first with other active same-material/printer/nozzle templates.
- Template and filament material-setting validation must show a strong red reason beside every invalid control, mark it with `aria-invalid`, connect the message through `aria-describedby`, and center plus focus the first rejected control. The page-level summary must name every rejected field and reason, including issues that cannot map to a rendered control. Unexpected failures show only the stable error code, HTTP status, and correlation reference needed to find the matching Diagnostics/log entry. Refresh a template immediately before editing it and keep genuine later optimistic-concurrency conflicts explicit. Never echo submitted values or internal exception details.
- Print settings and Templates use the shared read-only material comparator. Allow two to four current profile/template states, keep the first selection as the baseline, list only semantically different canonical/additional Cura settings, warn without blocking when printer or nozzle scope differs, and show exact-profile success rates with N/A for templates and a low-sample label below five ratings.
- The Cura Workstations page shows pairing and authoritative-library takeover only to Administrators and uses explicit Arch Linux/Windows labels. Open an unmistakable two-stage map-then-review dialog before takeover: list every reported Cura material file and saved print profile with a template selector whose default is **Do not import**, including named sources with zero tracked literal values. Show source type, machine, tracked-setting count, and omitted-expression count. A source and template may each be used once. **Back to mappings** must return to those selectors. Review every mapping and the ignored count together, then require one atomic **Complete takeover** confirmation that submits the exact reviewed source-ID set rather than the workstation row version. Do not duplicate that Cura-import action on Templates; keep live agent/synchronization health on Diagnostics. The warning must state that user material files are backed up and replaced and bundled materials are hidden.
- Cura Workstations distinguishes managed materials from unmanaged takeover sources and user-saved custom print profiles. It shows automatic recovery readiness and the ten newest exact-version automatic or named points before the separate recent backup-request history. Administrators may queue a named capture, edit its name/description, or confirm individual deletion. The restore dialog uses select-then-review confirmation, shows printer/quality/plugin/file counts, and states the required install, account login/plugin install, Cura close, restore, and conditional credential re-entry sequence. Never render raw snapshot file contents.
- After takeover, explain that edits to known managed Cura templates/profiles save directly and synchronize automatically, while adding new materials remains app-only.
- Use semantic HTML, visible focus states, keyboard navigation, 44px mobile touch targets, accessible labels, and icons plus text for status.
- Prefer compact, information-preserving desktop layouts: action rows wrap intrinsic-width buttons, repeated record cards use responsive columns when their minimum readable width is available, and shared cards, toolbars, tables, and section spacing use the established dense rhythm. Full-width action buttons are reserved for narrow mobile layouts or deliberately dominant single actions.
- Repeated Spool, Filament, Build Plate, and Nozzle rows/cards must remain equal in size within the selected presentation. Ellipsize single-line identity/fact text and line-clamp longer notes so content cannot resize one card. Filament and Nozzle list rows are directly keyboard/click navigable and have no redundant Open or Details button.
- Spools, Filaments, Build Plates, Nozzles, and Templates share a labelled **List**/**Cards**/**Detailed** dropdown beside search or page actions. Persist the selection independently per page in browser storage. Defaults are List for Spools, Cards for Filaments, Nozzles, and Templates, and Detailed for Build Plates. List uses flat information-dense rows, Cards uses compact responsive cards, and Detailed uses larger two-to-three-column cards. Preserve all actions through direct navigation or an accessible detail modal in every view. Detailed template cards may wrap their title, printer, nozzle, and facts instead of truncating available content. Templates show a useful setting value such as material flow rather than the identical managed-setting count, and additionally provide a versioned JSON export on every record plus an import dialog that explicitly creates a selected scope or confirms overwrite of one selected existing template.
- Capture wheel gestures once at the application boundary. When a focused numeric input receives a wheel gesture, blur it before the browser steps its value and allow the same gesture to scroll the page or modal. Do not block keyboard arrow keys or typed numeric entry.
- Respect `prefers-reduced-motion`. Keep motion purposeful and restrained.
- Keep the login experience formal and modern: use the approved Workshop Navy delta-printer artwork at `frontend/public/assets/login-delta-workshop.webp`, concise product-positioning copy, and a responsive two-panel composition that retains the artwork on mobile. Do not reintroduce the former trust-oriented login wording.
- The exact seven calibration steps may not be renamed or reordered. Size and Hole Calibration follows Retraction, collects X/Y/Z, hole, shaft, and wall measurements, shows expansion/flow/shrinkage results and geometry warnings, and clearly states that Klipper was not changed. After mandatory steps finish, show every derived suggestion and allow applying it to the filament or, with an exact-name confirmation, to the latest linked template; applied history is immutable and deleting an unapplied session requires confirmation. Preserve `P1` through `P5` as the initial physical plate set and naturally order exact Side A `P<number>` then optional Side B `P<number>b` meshes. Plate cards use the normalized uploaded plate picture when present.
- Build Plates groups sides beneath a compact responsive physical-plate card, exposes all physical metadata plus per-side material/finish/notes and completed-print count, and makes the active side explicit. Physical, picture, cleaning, side-selection, and mesh actions wrap at their natural width on desktop and expand for reliable touch use only on narrow mobile layouts. Its editor offers rectangular width/depth or round diameter fields exclusively and removes the selectable Other shape without breaking legacy records. Operators may add the one canonical Side B, which remains unavailable until its exact mesh is discovered; Moonraker state then synchronizes automatically.
- Nozzles manages physical records, one installed nozzle per printer, lifecycle history, exact completed-print counts, total filament use, and closed-Cura alignment of the exact linked position-zero extruder's existing definition-change container, selecting an exact variant when available. Printer pages link to the installed record rather than editing duplicate nozzle text and do not duplicate the Diagnostics action.
- A physical nozzle has one permanent printer owner and a code unique within that printer. Template cards show the printer directly below the title and the exact nozzle code, diameter, and material in their facts; never render the stored template description beneath the card title.
- Diagnostics owns connection, synchronization, worker, queue, per-actionable-job-type latest cause, bounded recent-error, running/latest-version, validation-result, projection-rebuild, retry, and reconciliation presentation. Display every immutable validation check included in its summary, explain that it reflects the recorded run time, and distinguish retained error history from current live conditions. Keep the server-generated **Download log** action beside Recent errors; do not assemble or sanitize the export in the browser. Other pages may link there but must not duplicate detailed operational status.
- Named solid filament colors use real swatches and a case-insensitive remembered palette. Permit arbitrary solid names, one to three product-specific multicolor samples, or Rainbow as a color; use the same physical spool silhouette on filament, spool, dashboard, and label swatches. Multicolor shows exactly its selected hard segments without sharing another multicolor product's palette, while Rainbow remains a distinct continuous fixed spectrum. Reopening the color control must show known colors while still allowing a new name. The color editor is available only before retained use and explains the lock afterward. Choosing a new sample for a remembered solid name must clearly explain that all matching existing and future solid filaments change together.
- Label previews use the server-rendered QR image with its conservative centered spool icon; do not add a second external color badge. Preserve the standard quiet zone and describe that only the stable spool URL is encoded.
- Spools shows the free-text bucket/location in its full-width catalog and selected-item detail modal; never reserve a permanent right-side selection panel. New-spool entry asks for purchased filament-only weight and optional full-spool scale weight, then previews inferred empty-spool weight. Purchase cost and currency derive a clearly labeled cost per gram in create/edit, inventory, and detail views. Administrators and Operators can correct every setup field, explicitly correct remaining mass, edit or clear location, and delete setup-only mistakes; explain archival when retained history exists and that Filament Manager synchronizes canonical values to Spoolman. The operational action is **Load spool**, never **Set active**: queue the physical Fluidd workflow, keep the current active indicator until load completes, and show concise pending guidance.
- Print History exposes exact-state and unresolved-legacy distinctions, inspection evidence, M600 segments, retained assessment history, and direct outcome entry without allowing historical snapshot edits.
- The application shell notification center polls persistent server events, shows unread count and severity, supports per-user read state, and routes to the affected workflow. Account password replacement takes over the screen until completed.
- On mobile, inventory, profile, activity, integration-job, label, synchronization, and print tables become compact cards rather than horizontal scrolling; retain their primary actions and 44px targets.
- All record creation and editing uses the shared accessible modal shell and visible `EditorSection` groups with a consistent header, scrollable body, and footer actions. Establish initial focus only when the modal mounts; changing a controlled input must never rerun focus setup. Do not hide editable options in `<details>` or page-specific fold-down forms. Persistent multi-step workflows may remain in-page but must use the same visible grouped sections.
- Operational Moonraker state on Dashboard, Spools, Build Plates, and Printers refreshes every 15 seconds. Dashboard leads with a large responsive printer card showing bounded Moonraker/Klipper availability, idle/printing/paused/finished/error state, progress and filename, and available nozzle/bed/chamber temperatures. Its status pill is substantially larger than ordinary status pills but must fit inside the existing card header without changing the card dimensions. Keep the inventory overview usable when live telemetry is unavailable and do not present an unreachable Moonraker endpoint as proof that printer power is off. Printer information refreshes server-side every 5 minutes; show freshness rather than a required manual synchronization action.
- Use shared tokens and components. Do not create one-off color, spacing, radius, or typography values when a token exists.
- Native form controls and their popup choices must use the active theme's semantic text and surface tokens; verify select menus in at least one light and one dark profile.
- Format displayed and prefilled values with shared helpers: zero decimals for temperatures, flow/fan, angles, and speeds; one for nozzles and ordinary dimensions; two only for tolerance, density, pressure advance, layer/line dimensions, and calibration evidence. Never expose canonical three-decimal storage formatting directly in the UI.
- The selected GUI color profile persists locally, defaults to the system-appropriate Workshop Navy variant, and remains in Settings rather than consuming navigation or mobile-toolbar space. Offer exactly three light profiles and five dark profiles. The shell shows the build version, a single icon-labelled Logout action without an account pill, and only left/right chevrons for collapse/restore.
- Keep same-origin navigation dependency-light through the shared History API router unless a reviewed feature requires a larger routing dependency.
