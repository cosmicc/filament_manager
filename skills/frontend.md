# Frontend Design and Accessibility Skill

- React, TypeScript, and Vite are the required frontend stack.
- Use the approved Workshop Navy light/dark palette in `docs/design/palette.png`; do not invent another palette.
- Use `docs/design/concepts/` as the layout and density reference. Preserve desktop data tables and use purpose-built mobile flows rather than squeezed tables.
- Navigation: Dashboard, Spools, Filaments, Profiles, Print History, Templates, Calibration Wizard, Build Plates, Printers, Nozzles, Labels, Integrations, Cura Workstations, Diagnostics, Activity, Settings.
- Templates exposes complete reusable current settings under the canonical `Template <material type>` identity. Filaments creates template-linked profiles with sparse overrides, renders every effective template value, visibly highlights customized fields immediately while editing, shows the linked template and inherited/customized counts, and provides per-setting **Reset to Template**. Group controls into Cura-like temperature, flow, speed, retraction, cooling, support, dimensional, filament, Klipper, and build-plate sections; never use an Advanced Cura catch-all. Cura aliases for retract speed and maximum fan speed remain one canonical editor control. Saving a template immediately updates every linked profile except its explicit customizations and automatically queues Cura synchronization.
- Template and filament material-setting validation must show a red reason beside every invalid control, mark it with `aria-invalid`, connect the message through `aria-describedby`, and use the page-level error only as a summary or for unmapped failures. Never echo submitted values from server validation details.
- Profiles and Templates use the shared read-only material comparator. Allow two to four current profile/template states, keep the first selection as the baseline, list only semantically different canonical/additional Cura settings, warn without blocking when printer or nozzle scope differs, and show exact-profile success rates with N/A for templates and a low-sample label below five ratings.
- The Cura Workstations page shows pairing and authoritative-library takeover only to Administrators and uses explicit Arch Linux/Windows labels. Open an unmistakable two-stage map-then-review dialog before takeover: list every reported Cura material file and saved print profile with a template selector whose default is **Do not import**, including named sources with zero tracked literal values. Show source type, machine, tracked-setting count, and omitted-expression count. A source and template may each be used once. **Back to mappings** must return to those selectors. Review every mapping and the ignored count together, then require one atomic **Complete takeover** confirmation that submits the exact reviewed source-ID set rather than the workstation row version. Keep an **Import from Cura** route on Templates and keep live agent/synchronization health on Diagnostics. The warning must state that user material files are backed up and replaced and bundled materials are hidden.
- After takeover, explain that edits to known managed Cura templates/profiles save directly and synchronize automatically, while adding new materials remains app-only.
- Use semantic HTML, visible focus states, keyboard navigation, 44px mobile touch targets, accessible labels, and icons plus text for status.
- Respect `prefers-reduced-motion`. Keep motion purposeful and restrained.
- The exact seven calibration steps may not be renamed or reordered. Size and Hole Calibration follows Retraction, collects X/Y/Z, hole, shaft, and wall measurements, shows expansion/flow/shrinkage results and geometry warnings, and clearly states that Klipper was not changed. Preserve `P1` through `P5` as the initial physical plate set and naturally order exact Side A `P<number>` then optional Side B `P<number>b` meshes.
- Build Plates groups sides beneath a physical plate, exposes all physical metadata plus per-side material/finish/notes and completed-print count, and makes the active side explicit. Operators may add the one canonical Side B, which remains unavailable until its exact mesh is discovered; Moonraker state then synchronizes automatically.
- Nozzles manages physical records, one installed nozzle per printer, lifecycle history, exact completed-print counts, and total filament use. Printer pages link to the installed record rather than editing duplicate nozzle text.
- Diagnostics owns connection, synchronization, worker, queue, bounded recent-error, running/latest-version, validation-result, projection-rebuild, retry, and reconciliation presentation. Keep the server-generated **Download log** action beside Recent errors; do not assemble or sanitize the export in the browser. Other pages may link there but must not duplicate detailed operational status.
- Named filament colors use real swatches and a case-insensitive remembered palette. Permit arbitrary names, one solid sample, exactly two or three multicolor samples, or rainbow; use the same physical spool silhouette on filament, spool, dashboard, and label swatches. Multicolor shows exactly its selected two or three hard segments, while rainbow remains a distinct continuous fixed spectrum. The color editor is available only before retained use and explains the lock afterward. Choosing a new sample for a remembered name must clearly explain that all matching existing and future filaments change together.
- Spools shows the free-text bucket/location in the table and detail panel. New-spool entry asks for filament amount and optional full-spool scale weight, then previews inferred empty-spool weight. Administrators and Operators can correct every setup field, explicitly correct remaining mass, edit or clear location, and delete setup-only mistakes; explain archival when retained history exists and that Filament Manager synchronizes canonical values to Spoolman. The operational action is **Load spool**, never **Set active**: queue the physical Fluidd workflow, keep the current active indicator until load completes, and show concise pending guidance.
- Print History exposes exact-state and unresolved-legacy distinctions, inspection evidence, M600 segments, retained assessment history, and direct outcome entry without allowing historical snapshot edits.
- The application shell notification center polls persistent server events, shows unread count and severity, supports per-user read state, and routes to the affected workflow. Account password replacement takes over the screen until completed.
- On mobile, inventory, profile, activity, integration-job, label, synchronization, and print tables become compact cards rather than horizontal scrolling; retain their primary actions and 44px targets.
- All record creation and editing uses the shared accessible modal shell and visible `EditorSection` groups with a consistent header, scrollable body, and footer actions. Do not hide editable options in `<details>` or page-specific fold-down forms. Persistent multi-step workflows may remain in-page but must use the same visible grouped sections.
- Operational Moonraker state on Dashboard, Spools, Build Plates, and Printers refreshes every 15 seconds. Printer information refreshes server-side every 5 minutes; show freshness rather than a required manual synchronization action.
- Use shared tokens and components. Do not create one-off color, spacing, radius, or typography values when a token exists.
- Format displayed and prefilled values with shared helpers: zero decimals for temperatures, flow/fan, angles, and speeds; one for nozzles and ordinary dimensions; two only for tolerance, density, pressure advance, layer/line dimensions, and calibration evidence. Never expose canonical three-decimal storage formatting directly in the UI.
- Theme choice persists locally, defaults to system preference, and remains in Settings rather than consuming navigation or mobile-toolbar space. The shell shows the build version, a single icon-labelled Logout action without an account pill, and only left/right chevrons for collapse/restore.
- Keep same-origin navigation dependency-light through the shared History API router unless a reviewed feature requires a larger routing dependency.
