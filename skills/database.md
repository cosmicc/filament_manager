# Database and Migration Skill

- PostgreSQL is required for development and tests that exercise persistence. SQLite is not a substitute.
- Use SQLAlchemy 2.x typed mappings and keep API schemas separate from ORM models.
- Use UUID primary keys, `TIMESTAMPTZ`, `NUMERIC`, `JSONB`, explicit foreign keys, and indexes that match query paths.
- Mutable canonical rows carry an integer `record_version`; HTTP updates require an expected version.
- Measurement, usage, audit, and accepted calibration results are append-only.
- `print_jobs` retains one exact immutable start-state/profile snapshot plus supported sliced/actual metadata and one sanitized bounded stored WebP thumbnail. `print_material_segments` is append-only per spool interval, including M600; every exact segment snapshot captures the spool cost-per-gram and currency basis used to derive historical cost without consulting mutable inventory. `print_assessments` appends revisions and never overwrites an earlier score. Pre-0.2.1 history remains explicitly unresolved when exact state cannot be reconstructed.
- Import each bounded Moonraker history record inside a nested transaction. Skip and class-log malformed legacy records without retaining their payload, then commit the successful-pass checkpoint so one bad row cannot leave Diagnostics at `never` while valid jobs are present.
- `nozzles` are physical inventory objects permanently owned by one printer, with case-insensitively unique codes inside that printer. Installation on a different printer is invalid. `nozzle_lifecycle_events` append install/remove boundaries, each printer has at most one active nozzle, and `print_jobs.nozzle_id` preserves exact attribution. Completed-print totals are derived from completed jobs; count each distinct spool across the start spool and M600 segments once per print.
- `material_templates` reference one exact physical nozzle and retain its printer and diameter for explicit scope display and validation. Permit only one active normalized material type for a physical nozzle; migrations must reject ambiguous legacy ownership rather than choosing silently.
- `diagnostic_runs` persist bounded sanitized recovery-validation results. `worker_heartbeats` report liveness without storing secrets or external bodies.
- `build_plate_maintenance_events` is the append-only source for cleaning and side-specific mesh events. Plate rows hold versioned day/print reminder thresholds plus a bounded sanitized WebP image, media type, checksum, and image version stored in PostgreSQL; never retain original upload bytes or metadata. `notifications` deduplicates shared conditions while `user_notification_states` owns per-account read timestamps; clear read states when a resolved condition recurs.
- `application_settings` stores versioned operational policy. G-code inspection currently accepts only `warn` or `block`, defaults to `warn`, and queues printer state synchronization in the same audited update.
- Schema changes require an Alembic migration plus upgrade validation against disposable PostgreSQL.
- Physical build-plate identifiers use exact uppercase `P<number>` values, with `P1` through `P5` retained as initial seeds. Printable Side A uses the unsuffixed code and Side B uses lowercase `b`; `P4` and `P4b` belong to one physical P4 plate. An Operator may add the sole canonical B side, which starts mesh-unavailable. Moonraker synchronization preserves physical and side metadata, tracks mesh availability per side, and never deletes a plate or side merely because its mesh is absent.
- Typed material-profile columns hold frequently used Cura values, including distinct regular and initial-layer build-plate temperatures. Only keys in the approved Cura Material Settings catalog may enter `cura_extensions`; brand/type are derived metadata and saved snapshots remain immutable.
- `filament_colors.normalized_name` is the unique NFKC/casefold identity for a shared solid color label. Matching solid product palette fields are projection mirrors updated transactionally with audit and outbox work. Rainbow is a fixed color spectrum; multicolor products own one, two, or three product-specific samples and do not share a remembered palette. Reject color changes after a filament has retained spool use or print history.
- `material_templates` are mutable printer/nozzle-scoped identities; `material_template_revisions` are hidden immutable settings snapshots. Every current material-profile snapshot links to the current template snapshot, stores a bounded sparse `setting_overrides` map, and caches the complete resolved state in typed columns plus `cura_extensions`. User-facing saves append immediately current snapshots with no draft/publication gate. Print speeds, smooth time, and approved acceleration keys are template-only. Every cooling control, pressure advance, and ironing value may be retained as a sparse profile override; an existing profile continues inheriting any value it has not customized.
- `cura_takeover_mappings` records the unique workstation/source to template choice from the one-time atomic takeover. A source may represent a material file or saved print profile. Each source and template may be used at most once for an agent; unmapped sources create no canonical material record.
- Takeover optimistic concurrency compares the complete reviewed source-ID set with the current reported set. These IDs hash the source content; never use the workstation row version because routine heartbeats are unrelated operational updates.
- Configured-system seeding idempotently creates one recommended ASA template and immutable initial snapshot per configured printer/current-nozzle scope when no ASA template exists. Never overwrite or reactivate an existing ASA template.
- `cura_managed_edit_receipts` makes workstation-reported edits to known managed GUIDs idempotent. It may reference the new current profile or template snapshot; unknown/new Cura GUIDs never create canonical records.
- `cura_recovery_snapshots` stores immutable sanitized exact-version Cura configuration payloads, deduplicated by workstation/installation/version/checksum. Automatic points are pruned to the newest fifteen per installation/version; named points do not consume that quota and remain until explicit deletion. `cura_recovery_restores` copies the immutable payload into an audited leased restore request so snapshot retention never invalidates active or historical work.
- Spool `location` is bounded free text. `location_authoritative` distinguishes an uninitialized legacy row from a deliberate canonical value or clear: adopt one non-empty Spoolman location only while false, then keep Filament Manager authoritative.
- New spool creation may infer tare from a full-spool gross reading minus entered purchased filament weight and records that creation observation atomically. Optional purchase cost divided by that net filament weight is the physical spool's derived cost per gram; preserve exact `NUMERIC` arithmetic and project the original total price plus net weight to Spoolman. Treat only this `initial-<spool UUID>` measurement as removable setup state: delete it with a setup-only spool, but archive instead once any later measurement, correction usage, print, calibration, or NFC reference exists. A current-remaining correction appends `operator_correction` usage and queues exact Spoolman weight projection.
- Terminal completed, failed, and cancelled print capture aggregates actual segment weight by exact spool, records one idempotent `moonraker_print` usage event per spool/job, and derives the target from immutable pre-print state. Preserve a lower value already imported from Spoolman to prevent double subtraction; never invent predicted use when Moonraker actual use is unavailable.
- Workers claim due outbox jobs with `FOR UPDATE SKIP LOCKED`, reclaim stale running jobs after the bounded lock timeout, and serialize each projected external object with a PostgreSQL advisory lock. Singleton reconciliation and migration tasks also use advisory locks. Store `outbox_jobs.aggregate_version` as `BIGINT` because manually requested system jobs use microsecond timestamp identities. Keep a recurring failure actionable while its replacement is pending; only a successful replacement supersedes older terminal rows of that type. A successful object projection also supersedes older failed versions of the same object, and a successful full Spoolman convergence supersedes reconstructable vendor/filament/spool upserts, but never deletes or explicit weight adjustments. Retain all superseded rows for history while excluding them from actionable Diagnostics counts.
- The one-minute Spoolman safety sweep imports remote usage before projecting all canonical vendors, filament products, and spools. A migration requeues Spoolman jobs left running, failed, or dead by the earlier incompatible custom-field contract.
- Normalize supported Spoolman remaining-weight readings to the canonical `NUMERIC(12,3)` gram precision before delta comparison, usage-event persistence, and idempotency-key construction so sub-milligram source precision cannot repeat an already recorded event.
- Docker web and worker startup automatically runs `alembic upgrade head` while holding the stable application migration advisory lock. Keep the lock timeout bounded, never log the database URL, and fail closed on upgrade errors.
- Canonical database backup ZIPs contain exactly `manifest.json` plus one `pg_dump` custom-format `database.dump`. Validate member paths/counts, sizes, PostgreSQL magic, manifest identity, and SHA-256 before import, download, or restore. Automatic retention applies only to scheduled archives; never let an imported recovery copy evict a newer automatic backup.
- A canonical restore is always offline. Stage it by exact archive UUID, stop web and worker, then use the dedicated restore command to create a pre-restore safety archive and run `pg_restore --single-transaction --clean --if-exists --no-owner --no-privileges`. Apply only forward Alembic migrations afterward and revoke every restored browser session.
- Existing calibration sessions receive the dimensional step through migration. Historical applied/cancelled sessions keep it as a non-required skipped record; active and ready sessions must complete it before settings are applied.
- Dimensional results retain all raw X/Y/Z, hole, shaft, and wall measurements. Only material-profile outputs such as expansion and flow are applied; printer correction percentages remain review evidence and never mutate Klipper.
- Database `filament_user` must never receive access to the `spoolman` database, and Spoolman credentials must never enter this application.
- The current remote-database contract explicitly disables PostgreSQL TLS for both applications because the database runs on a dedicated isolated network. Preserve SCRAM authentication, narrow `pg_hba.conf` rules, firewall isolation, and separate roles; never use this connection mode across an untrusted or shared network.
