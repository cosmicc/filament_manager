# Filament Manager Workstation Agent

The workstation agent is the outbound-only bridge between Filament Manager and Cura. Install it under the same desktop account that runs Cura on every Arch Linux and Windows 11 workstation.

It discovers Cura user-data versions, machine instances, sanitized existing material settings, saved print-profile settings, known managed-material edits, and desired-library drift. Before takeover, saved print profiles are read-only sources: global and first-extruder layers are merged, only Filament Manager's approved literal settings are reported, and Cura expressions are omitted rather than evaluated. An Administrator may map any reported source to one existing template or leave it unmapped, then complete the entire takeover atomically. The agent waits until Cura closes, backs up affected user files, and atomically installs Filament Manager's current `Template <material type>` and product material library plus its managed visibility/enforcement plugin. The plugin waits for Cura to finish initialization before aligning the Material Settings plugin's enabled list, merging currency-safe weighted product costs for Cura print estimates, and connecting machine/material enforcement. It preserves unrelated Cura cost preferences and removes only managed GUIDs that disappeared. It favorites Templates, groups manufacturer-less products under `Unknown`, removes only centrally managed material keys from user custom profiles, repairs recoverable duplicate sections, and quarantines malformed bounded files. Changes to approved settings on known managed materials save directly in Filament Manager and synchronize automatically, while new or copied Cura materials are never imported. While Cura is closed, the agent captures bounded sanitized copies of complete safe printer, extruder, definition-change, and quality configuration—including opaque start/end G-code—for ten server-side exact-version recovery points, then applies only explicitly confirmed restores after a local rollback backup. After a restore, it re-aligns the linked position-zero extruder's `machine_nozzle_size` and any exact installed variant with the nozzle recorded in Filament Manager. It never uploads credentials, endpoints, paths, account sessions, or plugin binaries. It has no listening port, and its credential can be revoked from Filament Manager.

After initialization, the managed plugin also repairs manual drift in the authoritative 55-key Material Settings selection and verifies every key against Cura's active machine definitions. It atomically records only a catalog checksum, expected/exposed counts, bounded missing/extra keys, required-plugin readiness, and verification time. The agent binds this value-free receipt to the current deployment manifest, adds bounded Material Settings/Klipper Settings package versions, and reports the result to Cura Workstations and Diagnostics.

The installers explicitly report fresh installation versus in-place upgrade. Matching Arch Linux and Windows uninstallers remove the per-user agent service/task and private agent files while leaving Cura's currently deployed managed library usable.
